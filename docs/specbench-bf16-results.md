# Spec-Bench 子集：本机固定长度投机解码测试

已完成四种配置各五轮：每轮相同的 12 个问题（摘要 6 个、RAG 6 个），共 240 条正式请求。每次单并发，输入 512、输出 256 token；预热不计入结果。五轮是重复测量，不是 60 个独立问题。

数据来自 [Spec-Bench](https://github.com/hemingkx/Spec-Bench)。这是该数据子集在本项目合并模型与 llama.cpp 上的长度受控测试，不是官方完整 Spec-Bench 成绩。模型为原有 Llama 2 7B + 中文 LoRA 合并产物及其 Q4_K_M 量化版本；Q4 GPU 无投机是本次投机对照，项目原始精度基线仍为 Merge BF16。

## 相对 BF16 纯 CPU 的整体部署收益

## 口径与限制

- 摘要与 RAG 是偏输入重叠的长上下文任务，未覆盖官方其余四类，也不能代表中文问答能力。样本按运行前确定的规则选取；512 长度预算下仅裁原有上下文，不用重复问题或无关文字填充。裁上下文会改变原任务并可能丢失证据，不能把本次输出当官方质量分数。
- 请求关闭提示缓存并忽略 EOS，固定产生 256 token；重复、复制或本可提前结束的回答也保留。结果描述此负载下的性能，尚未完成正式质量/PPL 验收，接受率或文本相同不等于质量通过。
- Decode 计时按 llama.cpp 的口径使用每请求 255 个计时 token；TTFT 是客户端收到首个非空文本 SSE 的时间，含请求和传输开销，不含模型加载。官方 Spec-Bench 完整调用 wall-time 吞吐与该 decode 指标不同。
- GPU 是整卡定时采样，包含桌面等其他占用，不是进程精确峰值；温度、频率、功耗与热漂移会影响结果。五轮统计只描述本次测量波动，不能消除小样本与运行环境限制。

固定数据版本和取样、命令见 [实验协议](specbench-subset.md)。官方协议参考：[评测循环](https://github.com/hemingkx/Spec-Bench/blob/fd2c1cd7d2201ef71db4c5f4e455008f017967bf/evaluation/eval.py)、[速度统计](https://github.com/hemingkx/Spec-Bench/blob/fd2c1cd7d2201ef71db4c5f4e455008f017967bf/evaluation/speed.py)。
